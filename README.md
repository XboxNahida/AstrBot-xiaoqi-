# AstrBot 定制优化版

基于 [AstrBot 原版项目](https://github.com/AstrBotDevs/AstrBot) 的本地定制快照，首次音色版导出日期为 2026-10-31，最近任务修复同步于 2026-11-04，模型预设与小七人格说明于 2026-11-03 更新，核心版本为 4.27.2。本项目与原版有定制差异，并非官方发行版。

## 任务模型选择与有限重连（2026-11-04）

- 网页后台任务默认 GPT6（`openai/gpt-6-sol`）、单次120秒、总共最多3次请求，即首次加两次重试；后台不启用备用模型。
- Gemini 通过 `pc_list_task_models` 获取网页原有下拉菜单的同一模型目录，可为不同任务指定模型、超时和最多请求次数；策略随任务持久保存，不修改共享提供器默认值。
- 首次请求失败由原聊天链沿用人格主动说明正在重连，中间静默，预算耗尽后再次汇报并询问是否换模型。恢复及换模型重试保留成功工具步骤，取消或过期通知不会误发。
- 修复任务超时参数未真正传到底层SDK的问题，稳定工具排列；缓存命中及计费优惠仍以模型服务和中转站实际支持为准。详见[任务模型选择与重连说明](docs/任务模型选择与重连说明.md)。

公开副本7模块251项测试、8项子测试及7项初始化与更新阻断检查通过，14个Python源码/测试UTF-8编译、Ruff关键检查及变动JS语法检查通过。

本次仅更新限定源码、合成回归和4项脱敏任务预设，保留人格、音色、启动器及内置更新阻断；不发布真实聊天、记忆、任务、密钥或云端回执。真实模型波动通知和QQ聊天效果仍需使用验收。

- 后台通知明确告知聊天模型：本次是机器人主动汇报，用户没有再次发消息或催促。沿用人格，但不能凭空责怪用户；进度只依据真实工具回执，不由任务目标猜测排版、安装或即将完成。

## 四类任务与 Gemini 直接管理（2026-11-04）

- 明确长期、短期、后台和历史四类定义，同一份说明进入聊天常驻提示、中枢和管理工具；长期与短期指未来安排，耗时较久的模型执行仍是后台任务。
- Gemini 通过 `pc_manage_tasks` 直接查询、分类、暂停、继续、取消、重试和管理历史；普通定时安排复用官方工具，查询和归档无需创建新的后台任务。各来源支持的操作见[四类任务管理说明](docs/四类任务管理使用说明.md)。
- 默认展示活动记录与完整数量，历史按需查看；创建安排完成不代表已执行，周期某一轮完成不代表整个安排结束。归档与取消分开，删除保留最小防重放标记且不删除工作文件。
- 修复长摘要截断 JSON、归档任务重试后仍隐藏、取消结果未知被误当作成功及活动关联历史删除保护，保留真实账号隔离和原执行授权。

## 后台直接只读查询与子代理路由修复（2026-11-04）

- 聊天模型常驻 `pc_read_background`，可分页查看本人后台任务、执行命令、文件操作、模型已输出说明、工具回执、互动脚本及持久提醒；查看详情不创建新任务，沿用当前人格、记忆和聊天主备模型。

## 全链路错误恢复（2026-11-04）

- 任务工具报错、参数错误及结果不明会持久反馈给模型，自主修正或查询核实；取消固定30步和固定纠错次数，完成状态由模型报告，真实权限、取消和防重复执行继续生效。
- 授权工具按当前配置动态提供，推理标签不再隐藏工具；工作区账户懒准备。脚本终态可交模型继续处理，包含原始要求和脱敏回执，不自动重跑已安排的工作。
- 互动通道支持续期和查看已有脚本，新通道由脚本决定输入响应策略；监听失败自动恢复，脚本调度不受慢聊天投递阻塞。
- 中枢格式错误就地纠正、失败决定不缓存；聊天和视觉明确故障尝试网页已有备用，故障视觉描述不缓存，正常错误文字引用不误伤。

既有身份授权、敏感数据、他人工作区与机器人核心写保护保持。仅合成接口和模型反馈链验收，不代替真实群聊、图片和互动效果验收；详见 [持久任务与共享工具](docs/持久任务与共享工具.md)。

- 执行路由不再把“漏列具体动作”推断为纯文字并清空工具。中枢用 `task_mode=tools/reasoning` 明确区分实际执行与纯文字；执行请求缺少模式时按已有授权保留工具，未知账号仍不能执行。
- 普通文档和源码可通过固定只读接口按本地绝对路径查询，不再要求模型先取得其他工作区的执行账号。密钥、凭据、私有运行数据、数据库和重解析路径仍拒绝读取，文本输出清理敏感字段与已配置密钥；写入及命令仍使用原受限账号。
- 互动通道漏传 `channel_id` 时返回明确的缺参数提示与 `list/open` 下一步，允许有限纠错，不再误报主动消息权限不足。实际撤权、越界写入和结果不明的副作用不会自动重播。

- 修复连续语音及同一回复多段语音被自动冷却误拦截的问题。
- 两份当前使用的参考WAV放在`发布预设/data/tts_voice_references/`，首次初始化自动补齐；已有运行文件不会被覆盖。对应关系见`音色配置说明.json`。

## 既有优化

- 同一消息在同一机器人上的中枢判定复用；多次钩子经过相同消息时复用已有决定，真实消息、媒体和任务变化仍可必要重判。
- 网页可独立切换群消息合批、上下文压缩、人格摘要和判定复用；本次预设四项均开启，合批窗口2.5秒，近期消息上限6条。
- 群聊明确@对象隔离，并抑制机器人之间不必要的接话；已发送回复的待处理队列正常回收，过期请求不能继续发送。
- 裸@回复明确绑定当前发言者，只承接同一发言者120秒内的最近未答消息；正常关闭回复生成器不再误报“主动回复失败”。
- 当前模型配置及小七、晚柠人格重新导出；保留按机器人分开的人格、聊天与后台任务分工和备用模型配置，真实密钥和私人运行资料已清理。

此前路由优化的运行版自动回归为208项测试及53项子测试通过；一轮真实群聊中7个中枢事件仅产生7次实际请求并复用13次，未见串台或互聊延续。这些是原运行实例的验证记录，不能代替重新配置后的部署验收；连续补话合并和裸@承接问题仍应做定向实聊测试。

## Windows 首次使用

1. 安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)；项目需要 Python 3.12 或以上版本，uv 可以管理 Python 环境。
2. 安装 [Microsoft .NET 8 Desktop Runtime（Windows x64）](https://dotnet.microsoft.com/download/dotnet/8.0)。请选择桌面运行时，启动器依赖 Windows Forms。
3. 在本目录打开 PowerShell，运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\初始化环境.ps1
   ```

4. 双击 `AstrBot启动器.exe`，点击启动；打开 <http://127.0.0.1:6185> 完成后台账号设置。
5. 在模型来源中填写自己的 API 密钥；在机器人配置中填写自己的平台凭据，再启用需要的机器人。导出预设中的机器人均默认关闭。
6. 检查人格、唤醒词、群聊允许范围、插件目标对象和表情库绑定；原来的私人群号、群友资料及素材库没有随包提供。

EXE 仅是启动管理器，不能代替 Python、依赖和机器人主程序。它必须与 `AstrBot-master` 文件夹放在同一级。若本机已有机器人占用 6185 端口，请先关闭原实例，避免打开原实例的后台。

自学习插件保留原有数据库类型配置；外部数据库地址、库名、账号和密码已清空，使用前须重新配置或在该插件设置中选择 SQLite。其他依赖外部服务的插件也需要重新填写凭据。
