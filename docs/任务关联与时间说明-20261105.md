# 任务关联与时间说明

Gemini仍负责按聊天语义管理任务，程序提供真实状态、时间和关联接口，不按相似标题自动合并或取消工作。

## Gemini收到的任务事实

- 当前任务：尚未结束的长期安排、短期安排和后台执行。等待输入、暂停、结果未知仍需关注，但不代表正在运行。
- 近期历史：已完成、已取消或已结束失败的记录，单独提供少量最近记录供理解上下文，不能当成待办。其余历史可用管理接口分页查询。
- 时间：创建、最近更新、结束、上次开始和下次执行分别标注，显示北京时间及`+08:00`。旧记录未保存的时间显示未知；查询不会刷新更新时间。
- 数量：`counts`表示实际执行/安排记录数，`group_counts`表示已经显式关联的目标数量。同一目标的初稿、修订可以是两条执行记录。
- 来源：后台工作完成不意味着它创建的定时安排已经结束；周期查询的一轮完成不意味着整个周期任务结束。

## 供Gemini选择的操作

- 新工作：使用`pc_submit_task_intent`正常提交。
- 同目标的新一轮执行：提交时传`related_task_id`，并选`relation=follow_up/revision/retry/related`。保留原执行、原结果和原检查点，新执行单独记录自己的完成证据。
- 关联已有记录：`pc_manage_tasks(action="link", source="background", item_id=源执行ID, related_item_id=目标执行ID)`。只能关联同机器人、同会话、同账号的真实记录；关联不会停止或恢复任何执行。
- 原文件没收到：先读取原结果，已有文件可直接调用`pc_task_send_files`补发，不必重建文件。
- 用户说够用、停止、不用再做：结合最近聊天，管理相关活动项并自然收尾；不要因为历史出现而重开任务。
- 结果未知：先核对原工具回执，避免重放已经产生副作用的操作。

## 聊天与主动汇报

聊天使用单个带边界的最新任务事实块。主动汇报沿用原人格、记忆、称呼和最近同会话聊天，但先替换保存的旧任务事实块，再读取当前清单。

主动汇报明确告知Gemini：这是自己汇报后台进展，不是用户新催促。通知没有执行工具，不能声称已经取消、重做或完成没有证据的工作。

集中说明位于`task_catalog.py`的`TASK_DEFINITIONS`、`TASK_GUIDANCE`，通知补充说明位于`task_runtime.py`的`render_notification`。本次未更改人格正文。
