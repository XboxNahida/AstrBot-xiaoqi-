# Gemini媒体与历史接口

本轮由聊天层结合人格、完整图文与上下文决定媒体动作。中枢仍判断是否参与和处理消息队列，不审批生图、改图、语音、演唱和点歌。网页启用状态、真实账号授权、工作区隔离及程序密钥保护继续生效。

## 图片

Gemini和后台共享`pc_generate_photo`。可选`aspect_ratio`（如`9:16`）、`resolution`（`1K`至`4K`或`1024x768`）；留空沿用网页默认。参数只作用于这次请求，不保存到全局配置；各图片接口仍可能有自己的尺寸限制。改图沿用已有图库选择、当前附件和参考图接口。

## 语音、唱歌和点歌

Gemini用`<pc_tts>正文</pc_tts>`选择普通语音，用`<pc_tts>(唱歌)歌词</pc_tts>`选择演唱，后者采用网页的独立唱歌音色。普通语音继续使用机器人绑定的音色。未选择语音的回复保持文字，聊天路由不再随机抽取语音或被旧后处理模式强制转换。

个人微信iLink当前实测原生SILK、MP3语音请求均返回消息ID，但客户端不显示；同一段音频作为MP3文件能够收到。因此微信的Record统一转换为“语音回复.mp3”文件发送，保留音色和内容，不补发文字原文。QQ等其他平台继续采用原有语音消息。API接收与客户端实际到达分别记录，空回执不算成功；只有message_id的合法回执仍兼容。

点歌、播放歌曲由Gemini通过`pc_submit_task_intent`发布后台搜索任务；后台`find_music`搜索、`deliver_music`发送，候选搜索或下载使用`search_music`。接口已注册不等于真实任务一定成功，结果仍以检索和发送回执为准。搜索歌曲与使用机器人音色演唱分开处理。

## 历史聊天和旧图

`pc_read_chat_history`不创建后台任务。默认读取当前对话；`resource=conversations`列出同一机器人、同一会话已保存的对话，之后可指定`conversation_id`。`query`搜索正文、`images_only`筛选含图记录；使用`offset`、`limit`及返回的`next_offset`分页。

返回用户/助手正文，不返回系统提示、工具结果或推理字段。原记录没有逐条时间时返回`null`，不能猜时间。仅包含已保存的LLM对话，不承诺覆盖群里所有未触发机器人的消息。

图片返回`image_ref`，交给`pc_inspect_images(source="history", image_refs=[...], question="...")`检查。引用绑定当前真实事件，不接受任意URL、文件路径或其他会话引用；原图过期时可能读取失败。已有图库的选择、回发和改图仍使用`pc_image_history`，两类ID不能混用。

## 提示词变更位置

- `main.py`的聊天请求接入：媒体工具选择、点歌后台搜索、历史查询及历史不能充当新授权的说明。
- `capability_hub.py`的中枢提示：媒体交聊天模型，不审批或派发；动作列表只作建议。
- `passive_state_pipeline.py`：聊天路由不再注入“中枢已批准动作”清单。
- `tts_enhancement.py`的`_build_tts_rule_prompt`：聊天层标签选择、演唱标签和点歌区分，仍沿用网页语种、音色和发送形态。
- `chat_history_reader.py`与`image_inspection.py`：工具schema和查询范围、时间未知、旧图引用用法。

本轮未修改任何人格说明或示例对话。
