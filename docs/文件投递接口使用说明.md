# 文件投递接口

前台Gemini和后台任务模型使用同一接口：`pc_task_send_files`。身份、机器人和接收会话由程序绑定，模型不能把文件改发给其他会话。已有任务授权保持不变，主要用户及其已授权群友使用各自工作区。

模型选择要发送的实际文件：

```json
{"paths":["公式渲染器.html"]}
```

单个文件原样作为附件投递。多个文件或目录默认打包ZIP，保留工作区内的相对目录结构，避免同名文件覆盖：

```json
{"paths":["文档/报告.docx","图片"],"archive_name":"处理结果.zip"}
```

`package`可以是`auto`（默认）、`zip`（强制打包）或`individual`（逐个发送）。可以使用当前账号工作区内的绝对路径；通过`pc_task_workspace`发现真实路径。交付不自动改变任务完成状态，也不在每次任务结束时强制发送文件。

## 数据保留和密钥保护

仅按机器人程序实际配置的密钥值检查，含全局/当前会话模型配置、插件密钥和程序内部互动通道凭据。普通源码、接口说明、业务数据、数据库导出以及包含token/password字段的正常配置完整保留，不能只凭字段名或文件扩展名拒绝。ZIP/Office包中的文件也检查实际程序密钥；命中时明确拒绝，不静默删改用户的有用内容。

路径越界、符号链接、Windows目录联接和硬链接仍不投递。先检查完整批次，再生成宿主临时快照；源文件不改动。资源上限为每批500个文件、100MiB，压缩包展开同限，最多4层；加密ZIP无法检查时返回错误，供模型选择解密后交付。平台自身大小、格式及账号权限限制仍由真实API回执说明。

## 发送事实

返回`items`包含文件名、大小和逐项状态。QQ只有拿到消息ID才返回`sent`；无可用会话或空上传明确不算成功。其他平台的成功仅确认适配器调用完成，不表示接收者已下载。

`unknown`表示发送结果不确定，可能已经发出；接口不自动重复发送。逐个发送发生中断时，保留前面已发送项目的回执，列出尚未尝试数量。模型根据实际回执自行检查、修复或解释，不把工具失败直接等同为整个任务失败。

用户可直接对小七说：“把刚才的公式渲染器作为文件发给我”；批量交付可说：“把这些结果打成一个ZIP发给我”。前台可以读取已有后台记录找到文件，然后直接投递，不必为查询再排一个后台任务。

## 本轮新增模型提示

- 文件工具说明：选择真实文件和打包方式，返回平台回执；代码正文和服务器路径不能冒充附件交付。
- 前台末级说明：已有文件可直接投递，本会话不新建查询任务；多文件/目录默认ZIP，按用户要求可逐个发；保护程序实际密钥，其他有用信息完整保留。
- 后台工作区说明：可调用文件工具向原会话交付产物；不能凭文件发送成功就断言整个任务完成。

完整源码位于插件`task_file_delivery.py`、`task_runtime.py`与`main.py`；本说明不替换原人格和聊天记忆。实际QQ收件需用户验收；本轮不向真实会话代发测试消息。
