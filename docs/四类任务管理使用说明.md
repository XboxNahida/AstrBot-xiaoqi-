# 四类任务管理说明

Gemini 是前台聊天与任务管理层。人格、聊天记忆和主备模型沿用现有配置。任务分类的定义来自同一份 `TASK_GUIDANCE`，每轮聊天、中枢判定和 `pc_manage_tasks` 工具说明使用同一文本。

| 分类 | 含义 | 示例 |
| --- | --- | --- |
| 长期任务 `long_term` | 持续或周期执行的未来定时安排 | 每天查询官方公告、每天早上提醒 |
| 短期任务 `short_term` | 一次性或阶段性的未来定时安排 | 十分钟后提醒、明早查询一次 |
| 后台任务 `background` | 用户提出要求后，由所配置的任务模型执行的实际工作 | 处理文件、编写脚本；等待输入、暂停、重试及结果未知仍属于需关注项 |
| 历史任务 `history` | 已完成、已取消或已结束失败的记录 | 已完成的文件处理、已取消的提醒、已结束的脚本 |

长期和短期不按固定分钟数区分；Gemini 可结合用户意思调整未来安排的分类。耗时较久的后台执行仍属于后台任务。

创建提醒的后台工作完成，不代表提醒已经触发。周期任务某一轮完成，不代表整个周期安排结束。官方一次性安排触发后可能从调度器删除，其后续执行以实际后台记录为准；不能凭调度器中缺失记录猜测执行成功。

## Gemini 的直接管理工具

`pc_manage_tasks` 绑定原始消息的机器人、会话与账号，不能靠传参冒充其他用户。

- `list`：查询四类完整数量、活动总数和分页记录；默认活动项，历史按需读取。来源不可用会明确标记，不能把不完整查询解释为没有任务。
- `detail`：查看后台步骤、脚本状态或定时安排详情；详细后台记录仍可使用常驻的 `pc_read_background` 分页读取。
- `classify`：调整未来安排的长期或短期属性，不改真实执行状态。
- `pause/resume/cancel/retry`：复用原执行服务的能力，返回真实回执。后台支持既有暂停、继续、取消和重试；官方定时支持暂停、继续和取消；脚本支持取消，逻辑修改或重建交给后台任务模型。
- `schedule`：复用现有官方 `future_task` 创建或修改普通定时安排；`task_kind=reminder` 为提醒，`monitor` 为联网查询。仍检查当前授权和工具是否启用，自定义脚本交后台处理。
- `archive/unarchive`：调整历史展示，不隐式取消、重试或执行任务。
- `delete`：清理已归档终态历史的正文和对应执行详情，保留最小防重放标记，不删除工作文件。仍有待发送回执、活动关联执行或反馈时，会返回具体原因。

新实际工作使用 `pc_submit_task_intent`。查询、分类及历史管理无需创建新的 GPT 等后台任务。

## 回执与恢复

只有成功回执才能说明对应操作完成。定时创建用“原始消息＋稳定操作键”防重复；结果未知先查询，不能换键盲目重建。取消未来安排不代表已经启动的后台执行也被取消。

等待输入、暂停和结果未知不会自动变成历史。失败历史可用原后台任务 ID 重试；重试后立即恢复为活动可见。只有明确删除了历史正文的墓碑记录不再允许重放。

本次功能不会自动归档、删除、重跑或重建现有任务。目录只新增展示元数据和操作去重表，原后台、互动脚本、官方定时服务仍负责执行事实。
