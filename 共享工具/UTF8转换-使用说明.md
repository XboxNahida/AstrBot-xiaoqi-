# 批量 UTF-8 转换工具

适用 Windows 自带的 PowerShell 5.1，无需安装 Python 或第三方库。

## 双击使用

1. 解压整个工具目录，双击 `启动工具.cmd`。
2. 在弹出的窗口中选择需要转换的文件夹。
3. 输入 `1` 输出 UTF-8（无 BOM），输入 `2` 输出 UTF-8 with BOM。直接回车默认选 `1`。
4. 选择是否递归处理子文件夹：输入 `Y` 或直接回车表示处理，输入 `N` 表示只处理当前文件夹。
5. 选择是否覆盖原文件：输入 `Y` 表示备份后覆盖，输入 `N` 或直接回车表示输出副本到 `converted`。
6. 完成后查看 `converted/conversion-report.csv`，了解成功、跳过、失败、源编码及备份位置。不覆盖时，转换结果位于 `converted`；覆盖时，转换结果就在原文件路径。

只处理 `.c`、`.h`、`.md`、`.txt`，扩展名大小写均可。不覆盖时原文件保留，输出副本保持相对目录结构。不会复制其他扩展名，因此输出目录不是完整的项目备份。

## 覆盖与恢复

- 默认不覆盖，原目录里的文件不会改变。
- 选择覆盖时，成功转换的文件会在原路径原子替换；被替换文件的原始字节保存在 `converted/backup-时间戳-唯一编号`，保留相对目录结构。
- 每次覆盖使用独立备份目录，不改写历史备份。跳过的文件保持原样；遇到锁定、权限不足等问题会在报告中记录失败。批次中其他文件可以继续转换，请检查报告。
- 恢复时，按报告里的“备份文件”路径，将需要恢复的文件复制回对应原路径。备份仅包含本次成功覆盖的目标文件，不是完整工程备份。
- 覆盖模式不会更新 `converted` 中旧的输出副本；应查看原文件路径和本次报告。

## 编码选择

- UTF-8（无 BOM）：通常适合 C/H 源代码、Markdown 和现代编辑器。
- UTF-8 with BOM：适合需要 BOM 标识的工具或旧版 Windows 文本处理场景。

有 BOM 的 UTF-8、UTF-16 和 UTF-32 会按其声明严格解码；无 BOM 时先严格尝试 UTF-8，不符合则尝试 GB18030（涵盖常见 GBK 中文文本）。无法解码、声明的 BOM 与内容冲突、含非文本控制字符的文件会跳过。允许常见换行、制表和换页字符。

**自动识别不是确定证明。** 无 BOM 编码仅凭字节不能唯一确定，报告会将 GB18030 标为“推定”。Big5、其他语言代码页、无 BOM 的 UTF-16/32 和原本已经乱码的文件不保证正确转换；请核对报告和中文内容。工具不会自动修复已有乱码。

## 输出目录注意事项

- `converted` 是工具专用输出目录，扫描时会排除它。
- 再次执行副本模式会覆盖当前成功转换文件的目标副本及报告；覆盖模式会更新原文件和报告，并创建新的备份。
- 不清理旧结果：原文件已删除或本次跳过时，历史副本可能仍在 `converted`，应以最新报告为准。
- 文件和目录链接不跟随；输出路径出现符号链接或目录联接时拒绝写入。
- 转换期间应避免其他程序修改源文件；建议先保存编辑器中的内容。
- 文件逐个读入内存，主要用于一般源代码和文档，不适合超大文本文件。

## 命令行使用

在工具所在目录打开终端，将示例中的文件夹替换为实际路径：

```powershell
# 当前文件夹，UTF-8 无 BOM
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Convert-ToUtf8.ps1 -SourceFolder 'D:\项目' -TargetEncoding UTF8

# 包括子文件夹，UTF-8 with BOM
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Convert-ToUtf8.ps1 -SourceFolder 'D:\项目' -Recurse -TargetEncoding UTF8BOM

# 包括子文件夹，备份后覆盖原文件，UTF-8 with BOM
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Convert-ToUtf8.ps1 -SourceFolder 'D:\项目' -Recurse -TargetEncoding UTF8BOM -Overwrite
```

不带 `-SourceFolder` 会进入交互模式。命令行仅在明确指定 `-Overwrite` 时覆盖原文件。启动器的执行策略选项只作用于本次进程，不更改电脑的全局执行策略；组织策略仍可能限制运行。

## 验证范围

已通过 Windows PowerShell 5.1 和 PowerShell 7.6.5 的真实样例转换验收：两种 BOM 输出、中文及 emoji、GB18030、带 BOM 的 UTF-16/32、空文件、异常文件跳过、递归、扩展名筛选、报告和重复执行。对样例原文件执行 SHA256 前后比对，无内容变化；脚本语法解析为 0 错误。

覆盖模式另行检查两种输出编码、备份与覆盖前文件的 SHA256 一致、递归排除输出及历史备份、异常文件跳过、锁定文件失败后内容不变，以及重复执行保留历史备份。

目录选择窗口及双击交互需在实际桌面使用时确认；不能用自动化样例通过代替图形交互验收。
